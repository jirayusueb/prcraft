# PR Craft

A desktop app for reviewing GitHub pull requests and GitLab merge requests in one place. Product intent: [PRODUCT.md](PRODUCT.md). Visual system: [DESIGN.md](DESIGN.md).

Pure Rust on egui, hosted by the craft-ui runtime from [storytold/craft-libs](https://github.com/storytold/craft-libs), laid out like the other Craft apps. Rules for contributors and agents: [AGENTS.md](AGENTS.md).

## Run

Needs Rust 1.95 or later. PR Craft reuses the logins of the `gh` and `glab` CLIs; it never asks for a token.

```
cargo run --release -p pr-craft            # desktop app
cargo run -p pr-craft-cli -- forge.status  # headless: login state of gh and glab, as JSON
cargo xtask ci                             # fmt, clippy, tests, layers: what CI runs
```

## Status

M6 of [ROADMAP.md](ROADMAP.md) (the AI engine, agents and runs, and the screens for them) on top of M5, without its platform part. The inbox lists open GitHub pull requests and GitLab merge requests that wait on your review. A change whose base branch is another open change's head branch joins that change's stack, and the inbox shows the stack as one entry. Back to you (B) lists the changes you reviewed with whose turn each is: one returns on new commits, an author reply, all your threads resolved, a new review request, an @mention or a dismissed approval, and an approval stays with the author unless it is dismissed. Notifications (N) keep those events and new review requests in the app, with seen marks and a pause. Banners, the Dock badge, the menu-bar item and the 10:00 digest are not built: they need platform code from craft-libs. Enter opens a change: read its own diff, jump between the layers of its stack, press S for the diff of the whole stack, or, from Back to you, press R for only what changed since your review (both read-only), or H to hand the review to someone else. Filter files, mark them viewed, write line comments that stay on this Mac, and submit them with a verdict as one review (⌘↵). File views: a Markdown, image, SVG or notebook file opens rendered, and ⇧S flips it to the source diff and back; the choice is remembered per file extension. Rendered Markdown marks changed blocks in words, shows removed text where it was, and a comment on a block (C) posts on that block's last changed source line. Images show 2-up (1), Swipe (2), Onion (3) and Difference (4); SVG shows both versions with a count of drawn shapes, groups and images; a notebook shows its cells with their text outputs and folds the unchanged ones. Comments on images, SVG and notebook cells are not pinned to a point or a cell: comment on a source line (⇧S). Text inside an SVG is not drawn, notebook outputs that are not text are named but not drawn, and a Markdown table shows as its source text. JSON, YAML, TOML, CSV and lockfile views are not built. Every step is also a `pr-craft-cli` command (`review.open`, `draft.add`, `review.submit`, `review.blob`, `review.set_view`, `review.views`, `stack.list`, `stack.whole`, `inbox.back_to_you`, `review.since_last`, `review.hand_off`, `notify.list`, `ai.review.start`, `run.list`, `draft.keep`, …).

AI review (⌥⌘A in a review) runs your review agents and a general pass on Claude Code. You set it up in Settings (⌘,): AI engine, Privacy (read rules, never-send patterns, secret redaction), Review agents and Repositories. The sheet shows which agent reads which file and previews the exact text that will be sent; Start is allowed only after that preview and is refused if the change moved since. Runs go on in the background: a pill in the title area, the Activity screen (⌥⌘J) with Stop, Kill and Kill and retry (a retry or "Run on these" names the agent, engine and files and asks before it spends usage, and reads only that agent's files), and a runs panel in the review. Findings arrive as AI drafts under their line; A keeps one as a draft, X discards it, and nothing posts until you submit the review. The engine runs Claude Code with no tools, so it reads only the redacted diff. Not built: Z.ai (no API call or key storage), skills text in prompts, subagents, starting runs on a review request or new commits, read scopes beyond the diff, system notifications for a stuck run (they wait on M4), the usage meter, merging duplicate findings, and slash commands in comments.

Share (⇧⌘I in a review, M8) makes a PNG of a review summary, a release note for your own change, or a stack's progress, at 1200×630, square (1080×1080) or Slack (1280×720). It shows titles, numbers and people, never code or comment text, and the repository name only when you turn it on. Copy image (⌘C) puts the picture on the clipboard, though macOS does not tell the app whether it took it; Save PNG (⌘S) writes into `~/Downloads`, creating each file exclusively so it never replaces or follows anything there, because the runtime gives apps no window for a save dialog. `pr-craft-cli share.render` returns the model and the SVG, and `pr-craft-cli share.save '{"kind":"review_summary","change":{…},"size":"wide1200x630","path":"/tmp/image.png"}'` writes the PNG and refuses a path that already holds a file unless the params say `"replace": true` (the result says whether it replaced one); `share.copy` exists only in the app. Text is set in the system fonts (Geist when installed, else Helvetica Neue), because no font ships with PR Craft. The verdict on the image is the one you set on this Mac and is marked "not posted"; with nothing written it reads "Not chosen". Not built: checks and approvals on the image (PR Craft does not read them yet), merged layers in a stack (forges list open changes only), and rewriting the headline with the AI engine; you write the summary line yourself.

Settings (⌘,) also has Appearance, Accessibility, Keyboard, Offline and sync, and Permissions (M9). Theme (light, dark, or match macOS), fonts, sizes, density and the accessibility switches apply at once and are kept in `settings.json` in the data folder; so are rebound shortcuts (`keys.json`). Every shortcut is in one table (`keys.list`, `keys.rebind`, `keys.reset`), rebindable on the Keyboard page by pressing the new keys, and a binding that macOS owns, that another action in the same place uses, or that would swallow typing is refused with the reason; another app's chord is allowed with a warning. The inbox re-checks its sources every 5 minutes (1, 5 or 15, slower on battery by default; battery state comes from `pmset`). Not wired: the code colour theme (the diff has no syntax colours), announcing new drafts to VoiceOver, applying "if the PR changed while offline" (there is no post queue), and reading macOS permission status (the Permissions page opens the right System Settings pane but cannot say whether a grant is on). Commands: `settings.get`, `settings.set`, `keys.list`, `keys.rebind`, `keys.reset`.

The review screen also has the last M2 frames. Split view and diff options (`L`, `O`, `W`, `⇧W`, `⌥Z`) save per repository through `review.set_layout`; split needs a window 1280 px wide. Hidden context (`review.expand`, `⇧K`, `⇧J`, `⌥E`) reads the file at the commit on screen. Review threads (`thread.list`) show under their line with a reply field; Reply now and Resolve thread (`⇧R`) write to the forge at once, not with Submit, and were never run live here. Commits to review (`⇧C`; `,` and `.` step one commit; `review.commits`, `review.range`) shows a run of commits read-only. The command palette (`⌘K`, `palette.query`) lists only actions, changes and settings pages that exist. Not verified: the GitLab side of threads and commits (fixtures only), and the palette against the running app.

Open locally (`⌘O` in a review, or Open in the title bar or the palette; frame 96) puts a change on this Mac. It uses only folders you name in Settings → Repositories: a checkouts folder, and per repository the folder of your clone, which must be the top of a git repository with a remote that is that repository on that host. Each row of the popover shows the command it runs. Check out in a worktree (`⌘⇧O`, `checkout.worktree`) fetches the change's head into a ref of its own (`refs/pr-craft/<cli>-<n>` in your clone), checks it is the commit the forge names, and adds a detached worktree under the checkouts folder, one folder per change; your clone's own branch does not move. A worktree that is already there is reused only when it has no changed or staged files, and the result says when it is at a different commit than the PR head. A worktree that fails to build is removed again. Check out here (`checkout.here`) runs `gh pr checkout` or `glab mr checkout` in your clone, pinned to the host the clone was matched on, and only after you confirm the clone and the branch it names. Before it runs, it fetches the head and compares it with the clone's HEAD, so every file the switch rewrites counts, not only the files in the change's diff; git itself says which untracked and ignored files are at those paths, folding case and Unicode form as the volume does. When the CLI is done, the clone's HEAD must be the commit PR Craft checked, or the result says it is not (the CLI fetches again on its own, so the PR may have moved). It refuses, and says why, when the clone has uncommitted changes or conflicts, is in a merge, rebase, cherry-pick, revert or bisect, is on a detached commit nothing else reaches, or has an untracked or ignored file that the switch would overwrite (case differences count, as on the default macOS volume); it never stashes, resets, cleans or forces. Git hooks are switched off for the forge CLI and for every git command PR Craft runs here (`core.hooksPath=/dev/null`, set after any `GIT_CONFIG_*` entries your environment has; Check out here refuses on a git older than 2.31, which would ignore it), so a hook a change brings cannot run; your own hooks, such as git-lfs's `post-checkout`, do not run for these commands either. Every git, `gh` and `glab` command has a deadline, and one that runs out is stopped with the commands it started. Open in VS Code (`code -g`), Xcode (`xed -l`), Zed or Terminal (`checkout.status` reads, `open.editor` launches) opens the selected line of the current file from the worktree, or from your clone when it is at the change's head commit, and never a path outside it. `checkout.status`, `checkout.worktree`, `checkout.here` and `open.editor` run from `pr-craft-cli` too. Tested against throwaway repositories under the temp folder with a local bare remote. Not verified: a real `gh pr checkout` or `glab mr checkout` (only their arguments and environment are tested), a real fetch from GitHub or GitLab (`refs/pull/N/head` and `refs/merge-requests/N/head` are tested against a local remote that carries them), a timeout on a real stalled fetch, and the editors starting (only their argument lists and the lookup of their commands are tested). A remote that is an `~/.ssh/config` alias instead of the server's name does not match; the editor choice in Appearance that frame 96 mentioned is not built.

Known limits of Open locally: an untracked nested git repository at a path the change brings is not seen by the check before the switch (git refuses that switch itself, so nothing is lost, and the refusal arrives as git's own message after the fetch). The set of files the switch rewrites assumes it goes straight from the clone's HEAD to the change's head; if a local branch named like the change already exists, `gh pr checkout` goes through that branch's old tip first, and a file that differs only between HEAD and that tip is not checked, which only the check of HEAD after the switch reports.

A post to the forge that runs out of time (120 s) is not retried or forgotten: the CLI was stopped, but the forge may have taken the post, so the message says "The post may already have gone through: check the PR before posting again." A review keeps its drafts and verdict and is marked as having an unknown post (`post_unknown` in `review.local`). The next Submit asks first ("I checked: post again", or `confirm_unknown` in `review.submit`); a thread reply or resolve keeps its text in the field and shows the same words.

Interaction states (frames 102–110) are in every control: hover steps up one tone, pressed two, a graphite pill goes Stone/800 then Stone/900, and the focus ring (2 px with a 2 px gap) shows only after a key press unless Accessibility keeps rings on. Right-click, or ⇧F10 on a focused row, opens an app-drawn menu on a queue change (Open review, Open on the forge `⌥↵`, Copy link `⇧⌘C`), on a diff line or the selected lines (Comment, Copy lines `⌘C`, Open in VS Code, Hide whitespace, Mark file viewed), on a folder of the Files list (Mark folder viewed `⇧V`, fold `←` `→` `⌥←`, Show only or Hide this folder, Copy path `⌥⌘C`) and on a thread card (Reply, Resolve, Next and Previous thread, Open on the forge). Every item runs the same code as its key or button; ↑ ↓ ↵ Esc work, and Esc returns focus to the control that had it. A hovered diff line, unified or split, shows a comment button in its gutter (a split half anchors its own side; a removed-only line anchors old); a click comments on the line and a drag selects a range. Empty states say what is empty and never claim "caught up", "nothing is running" or "nothing matches" over a source that is paused, failed or still answering, or over runs that could not be read. Local drafts (D) lists every change with drafts, a pending verdict or a possibly-sent post, read from this Mac's saved reviews by `review.drafts_all` without asking a forge; its empty state says "No drafts on this Mac" only when every saved file was read. Not built: Snooze, Done and Mark as unread (PR Craft keeps no inbox state), Suggest a change, Ask Claude Code on a selection, Copy link to lines or a thread, Reveal in Finder, a file tree (folders are labels over the Files list), and file tabs. Frames 102–110 are rendered by `cargo test -p pr-craft-ui-egui --features renders --lib parity::renders` into `.egm/parity/app`.

Your changes (`Y`, M7 without Babysit, frames 27, 75, 97, 94, 88, 89) lists the open pull and merge requests you wrote, per signed-in host, from `mine.list`: `gh api graphql` (one search) and `glab api merge_requests?scope=created_by_me` (one page of 100, then the pipeline, approvals, threads and size of each read on their own). Rows show +added −removed and one status line (draft, conflicts, changes requested, checks failed, thread waiting, approved, behind, running, passing); an ember dot marks a reviewer waiting on you, and those changes also come back in Back to you (`inbox.back_to_you` carries them as `yours`, and as notifications). A failed host, a full page, a paused CLI and a failed re-check are said above the list, and an empty list says "no open changes" only when every source answered in full. The reading pane (`mine.detail`) shows the head line, a checks banner with View log, and the card for the state: a draft (reviewers and labels from `pr.collaborators` and `pr.labels`, one page each; `pr.ready`, `pr.set_reviewers`, `pr.set_labels`), a conflict, or the merge card (`merge.start`, `merge.queue`, `merge.auto`; approvals and check counts are the forge's, a queue is shown only when GitHub reports one, linked issues only when it names them). Merging, queueing, Merge when ready and `checks.rerun` need `confirm: true` from the CLI and a confirm step in the app that names the method and the branch; nothing is sent without it. Every write goes through the write path of the forge crate: a call that runs out of time says "The post may already have gone through: check the PR before posting again" and the pane reads the change again. The CI log (`checks.list`, `checks.log`) shows the last 2000 lines of a job with failing lines tinted by a keyword match and marked "!", and says when it was cut. Not built, and said in the UI: Babysit (no Off, Ask or Auto controls), the AI conflict fix and failure explanation, the names of conflicting files (neither forge gives them), assignee and milestone rows, reviewer reasons ("owns CODEOWNERS"), a draft reply in a thread, a GitLab rebase merge (the project sets the method) and GitLab merge trains. Not verified live: every write (none was sent), and GitLab reads this session (the host did not resolve); see `.egm/m7a/notes.md`. Renders: `.egm/parity/app/{27,75,97,94,88,89}-m7.png`.
